# Bus Fare Compliance Backend

This Dockerized FastAPI service accepts ESP32-CAM face images and Arduino Uno RFID events. SQLite stores users, face encodings, trips, payments, and fines in `fare_enforcement.db`.

## Debian 12 deployment

Install Docker Engine and Compose, then grant the deployment user access to the Arduino device:

```bash
sudo usermod -aG dialout "$USER"
# Log out and in again after changing the group.
cp .env.example .env
docker compose up --build -d
curl http://127.0.0.1:8000/health
```

### Automatic startup and deployment

Copy the repository to `/opt/camera_project` (or update the paths in `fare-system.service`), then install and enable the unit as root:

```bash
sudo install -m 0755 deploy.sh /opt/camera_project/deploy.sh
sudo install -m 0644 fare-system.service /etc/systemd/system/fare-system.service
sudo systemctl daemon-reload
sudo systemctl enable --now fare-system.service
sudo systemctl status fare-system.service
```

The unit runs `deploy.sh` after Docker starts. The script pulls `origin/main`, sets `/dev/ttyACM0` to mode `666` when present, rebuilds the Compose service, prunes unused images, and prints its status. For a `/dev/ttyUSB0` reader, set `ARDUINO_DEVICE=/dev/ttyUSB0` in the environment used by the service or update the script default.

The default Compose mapping is `/dev/ttyACM0`. For `/dev/ttyUSB0`, set `ARDUINO_DEVICE=/dev/ttyUSB0` in `.env`. If no reader is connected, the service continues when `SERIAL_REQUIRED=false`.

## API

`POST /api/scan-face` accepts a multipart field named `image` containing JPEG or PNG data. The first recognized frame creates an active passenger; after the debounce window, a later frame closes the trip and issues a fine when RFID payment was not recorded.

```bash
curl -F image=@face.jpg http://SERVER:8000/api/scan-face
```

`POST /api/payment` is also available for a network validator. The Arduino worker uses the same operation internally:

```bash
curl -X POST http://SERVER:8000/api/payment \
	-H 'Content-Type: application/json' \
	-d '{"rfid":"A1B2C3D4"}'
```

`POST /api/register-user` accepts multipart fields `name`, `rfid_uid`, and `image`. RFID payment can also be sent through `POST /api/payment`; the serial worker accepts the same JSON payload from the Arduino.

## Enrollment

The registration endpoint stores a 128-value `float64` encoding generated by the same `face_recognition` model used by the service. Do not pickle untrusted face data. Enrollment authentication should be added before exposing this endpoint beyond the trusted bus network.

The face lookup currently scans users in the database. For a large central user base, migrate this lookup to pgvector or FAISS and retain the threshold check.
